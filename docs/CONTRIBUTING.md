# 変更を入れるときのルール

このリポジトリでは、`main` への変更はすべて Pull Request（PR）で入れます。
`main` へ直接 push はできません（`scripts/setup-repo.sh` で入れた ruleset が止めます）。

## PR を出すときのルール

1. **CHANGELOG.md を更新する**。`## 未リリース` の直下に変更内容を 1 行の箇条書きで足し、行末に対応する Issue 番号を `(#1)` の形で書く

   ```
   ## 未リリース
   - 送料無料までの残額を注文確認ページに表示する (#1)
   ```

2. **Issue と PR をつなぐ**。PR の本文かコミットメッセージに `Closes #1` を書く（マージすると Issue が自動で閉じる）
3. **テストを通す**。`npm test` がすべて成功していること

1 と 3 は GitHub Actions が確認します（チェック名 `changelog` と `test`）。両方が緑になるまでマージできません。
1 はローカルでも `npm run check:changelog` で確認できます（PR のブランチで実行）。
ドラフト PR の間は `changelog` は走りません。「レビュー準備完了」（Ready for review）にしたときから確認されます。

## リリースするとき（このハンズオンではやりません）

`## 未リリース` の中身を `## 0.4.0 - 2026-MM-DD` のような見出しの下に移し、`package.json` の `version` をそろえます。
